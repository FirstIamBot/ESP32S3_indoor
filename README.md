# Метеостанція OUTDOOR / INDOOR (ESP32 + ESP-NOW)

Система з двох ESP32-пристроїв, що обмінюються даними по ESP-NOW і разом формують повну картину погоди: дані з інтернету (OpenWeatherMap), локальні датчики та дані з виносного бездротового вузла.

## Загальна архітектура

```
┌─────────────────────┐        ESP-NOW (unicast)        ┌──────────────────────────┐
│      OUTDOOR         │ ───────────────────────────────▶ │         INDOOR            │
│  ESP32-S3, батарея    │                                  │  E-paper дисплей (EPD47)  │
│  ESP-IDF v5.5.4       │ ◀─────────────────────────────── │  Arduino/PlatformIO       │
│  BME280/BMP280        │        sync ACK (timestamp)      │  OpenWeatherMap + локальні │
└─────────────────────┘                                    └──────────────────────────┘
```

- **OUTDOOR** — веденний пристрій. Прокидається, читає власні датчики, надсилає дані на INDOOR і йде спати.
- **INDOOR** — ведучий пристрій. Прокидається, отримує погоду з інтернету, читає локальні датчики, чекає дані від OUTDOOR, виводить усе на екран, надсилає OUTDOOR команду синхронізації сну і сам засинає.
- Обидва пристрої узгоджують **Deep Sleep рівно на 30 хвилин**, синхронізуючись між собою через timestamp у ESP-NOW-пакеті підтвердження (sync ACK), а не просто фіксованим таймером — це компенсує дрейф внутрішнього RC-генератора OUTDOOR і тримає обидва пристрої "в фазі".

### Життєвий цикл одного 30-хвилинного циклу

1. **INDOOR** прокидається за таймером Deep Sleep → підключення до WiFi → запит погоди з OpenWeatherMap → читання локальних датчиків → базовий вивід на екран.
2. **INDOOR** одночасно слухає ESP-NOW у фоні (до 10 хв очікування).
3. **OUTDOOR** прокидається за своїм таймером Deep Sleep → читає BME280/BMP280 + батарею + сонячну панель → надсилає структуру даних напряму на відомий MAC INDOOR.
4. **INDOOR**, отримавши дані від OUTDOOR: доповнює екран (температура/вологість/тиск/батарея/сонячна панель ззовні) → **одразу після виводу на екран** надсилає OUTDOOR unicast-підтвердження (`sync ACK`) з кількістю секунд до свого наступного пробудження, розрахованою від NTP-часу з прив'язкою до 30-хвилинних меж годинника (`:00`/`:30`).
5. **OUTDOOR**, отримавши sync ACK, використовує це число як тривалість Deep Sleep (замість фіксованого запасного інтервалу) і одразу засинає.
6. **INDOOR**, одразу після відправки ACK, теж іде спати (Deep Sleep 30 хв).

Якщо OUTDOOR не з'явився за 10 хв — INDOOR засинає без синхронізації (запасний фіксований інтервал на наступний цикл). Якщо INDOOR не встиг отримати NTP-час (наприклад, збій мережі) — sync ACK все одно надсилається, але з фіксованим (не вирівняним по годиннику) інтервалом, аби OUTDOOR завжди отримував якусь відповідь.

## OUTDOOR (`app_main.c`)

**Платформа:** ESP32-S3-DevKitC-1, ESP-IDF v5.5.4
**Живлення:** акумулятор + сонячна панель (постійно у Deep Sleep між циклами)

### Апаратна конфігурація

| Призначення | Пін / параметр |
|---|---|
| BME280/BMP280 (I2C) | `CONFIG_I2CDEV_DEFAULT_SDA_PIN` / `CONFIG_I2CDEV_DEFAULT_SCL_PIN` |
| Батарея (ADC, дільник напруги) | GPIO10 (`ADC_CHANNEL_9`) |
| Сонячна панель (ADC, дільник напруги) | GPIO11 (`ADC_CHANNEL_0`) |
| Статусний LED (WS2812, адресний) | GPIO48 (вбудований на ESP32-S3-DevKitC-1) |
| WiFi канал ESP-NOW | Канал 1 (`WIFI_CHANNEL`) — має збігатись з каналом роутера, до якого підключається INDOOR |

### MAC-адресація

INDOOR ідентифікується **фіксованою**, прошитою константою (без broadcast discovery):
```c
static const uint8_t indoor_mac[6] = {0x7C, 0x9E, 0xBD, 0xD2, 0x62, 0x58};
```
При старті OUTDOOR одразу реєструє цю адресу як ESP-NOW пір — жодного пошуку не відбувається.

### Структура даних (`sensor_data_t`, 30 байт, `packed`)

```c
typedef struct __attribute__((packed)) {
    float   temperature;      // °C
    float   humidity;         // %
    float   pressure;         // Pa (сирі паскалі, НЕ hPa!)
    float   battery_voltage;  // В
    uint8_t battery_percent;  // %
    float   g_solar_voltage;  // В
    uint8_t solar_percent;    // %
    int64_t timestamp;        // мс з моменту старту чіпа (esp_timer_get_time()/1000)
} sensor_data_t;
```

### Структура sync ACK (`espnow_sync_ack_t`, 5 байт)

```c
typedef struct __attribute__((packed)) {
    uint8_t  magic;            // 0xA5 - відрізняє від sensor_data_t за розміром/магічним байтом
    uint32_t next_wake_in_sec; // скільки секунд спати (від INDOOR)
} espnow_sync_ack_t;
```

### Робочий цикл (`app_main()`)

1. Ініціалізація NVS, LED, ADC, WiFi (STA, фіксований канал), ESP-NOW, I2C.
2. Реєстрація INDOOR як ESP-NOW піра (фіксований MAC).
3. `read_sensors_once()` — одноразове зчитування:
   - Примусовий запуск вимірювання BME280/BMP280 (`bmp280_force_measurement`) + очікування завершення конверсії (`bmp280_is_measuring`), інакше в режимі FORCED повертались би застарілі дані з попереднього циклу.
   - Читання батареї та сонячної панелі через ADC (з калібруванням, якщо доступне).
   - LED індикація: **зелений** під час читання.
4. Відправка `sensor_data_t` на INDOOR.
5. Очікування sync ACK до 3 сек.
6. Визначення тривалості сну: значення з ACK, якщо отримано, інакше запасні 30 хв (`DEEP_SLEEP_INTERVAL_SEC`).
7. LED індикація підсумку: **синій/зелений** — успіх, **червоний** — помилка.
8. `esp_deep_sleep_start()`.

### LED-індикація

| Колір | Значення |
|---|---|
| Зелений | Читання сенсорів у процесі |
| Синій/зелений | Успішна відправка даних |
| Червоний | Помилка (сенсор, відправка, ADC) |

### Тестовий режим

```c
#define TESTING_DISABLE_DEEP_SLEEP
#define TEST_MODE_DELAY_SEC 5
```
Якщо визначено — Deep Sleep не використовується, цикл (читання → відправка → очікування ACK) повторюється кожні 5 секунд у нескінченному циклі. **Обов'язково закоментувати перед реальною експлуатацією на батареї.**

## INDOOR (`OWM_EPD47_epaper_v2_5.ino`)

**Платформа:** ESP32 (Arduino/PlatformIO), e-paper дисплей EPD47 (4.7", 960×540)
**Джерела даних:** OpenWeatherMap (інтернет), локальні датчики, ESP-NOW від OUTDOOR

### Апаратна конфігурація

| Призначення | Пін |
|---|---|
| Кнопки | S2=GPIO34, **S3=GPIO35** (пошук нових сенсорів), S4=GPIO36, S6=GPIO4 |
| Сенсорна панель | GPIO13 (`TOUCH_PANEL`, `TOUCH_INT`) |
| WiFi канал ESP-NOW | Канал 1 (`ESPNOW_WIFI_CHANNEL`) — визначається каналом роутера, до якого фактично підключений INDOOR |

### Список відомих сенсорів (NVS)

Замість жорсткого хардкоду одного OUTDOOR, INDOOR веде **список MAC-адрес відомих сенсорів** (до 8, `MAX_KNOWN_SENSORS`), який зберігається в NVS (`Preferences`, namespace `"sensors"`) і завантажується при кожному старті. При першому запуску (порожній NVS) автоматично додається типовий сенсор за замовчуванням.

**Додавання нового сенсора:**
1. Натиснути кнопку **S3** — вмикається режим пошуку на 60 секунд (`DISCOVERY_MODE_DURATION_MS`).
2. Поки режим активний, пакет правильного розміру (30 байт) від будь-якого невідомого MAC реєструється як новий сенсор і зберігається в NVS.
3. Режим пошуку вимикається одразу після знаходження нового сенсора (або через 60 сек, якщо ніхто не з'явився).
4. Поза режимом пошуку пакети від невідомих MAC ігноруються (захист від сторонніх ESP-NOW пристроїв в ефірі).

INDOOR **не йде спати**, поки триває активний пошук — інакше WiFi/ESP-NOW вимкнуться раніше, ніж новий сенсор встигне озватись.

### Обробка вхідних даних (`OnEspNowRecv`)

- Перевіряє MAC відправника проти списку відомих сенсорів.
- Логує кожен прийнятий пакет, включно з розшифрованими значеннями (T/H/P/батарея/сонячна панель/timestamp) для діагностики.
- Розрізняє пакет даних (30 байт, `espnow_sensor_msg_t`) від sync ACK (5 байт) за розміром.
- Запам'ятовує MAC відправника (`lastSenderMac`) — sync ACK надсилається йому пізніше, вже з `loop()`, а не одразу з колбека.

### Структура `espnow_sensor_msg_t` (30 байт, ідентична `sensor_data_t` на OUTDOOR)

```c
typedef struct __attribute__((packed)) {
  float   temperature;
  float   humidity;
  float   pressure;       // Pa - при відображенні ділиться на 100 для hPa
  float   batteryVoltage;
  uint8_t battery_percent;
  float   g_solar_voltage;
  uint8_t solar_percent;
  int64_t timestamp;
} espnow_sensor_msg_t;
```

⚠️ **Критично:** ця структура має побайтово збігатися з `sensor_data_t` на OUTDOOR (порядок полів, типи, розміри) — будь-яка розбіжність спричиняє мовчазне відкидання пакетів через невідповідність `sizeof()`.

### Робочий цикл (`setup()` + `loop()`)

1. `setup()`: WiFi STA → `StartEspNowListener()` (реєструє відомих сенсорів як пірів, читає NVS) → підключення до роутера → NTP → погода з OWM → локальні датчики → базовий вивід на екран.
2. `loop()`, щоцикл:
   - Опитує кнопку S3 (`CheckDiscoveryButton()`).
   - Якщо режим пошуку активний — очікує, не спить.
   - Якщо дані від OUTDOOR прийняті (`espNowDataReceived`): виводить їх на екран (`GetEspNowData()` → `DisplayWeather()` → `edp_update()`), одразу надсилає `SendSyncAck()` на MAC відправника, і одразу `BeginSleep()`.
   - Якщо дані ще не прийшли і не минуло 10 хв (`OUTDOOR_MAX_WAIT_MS`) — продовжує чекати.
   - Якщо 10 хв вичерпано без даних — засинає без синхронізації.

### Формування sync ACK (`SendSyncAck()`)

```c
time_t now = time(nullptr);                     // Unix-час з NTP
localtime_r(&now, &timeinfo);                   // -> tm_min, tm_sec
secIntoWindow = (tm_min % SleepDuration)*60 + tm_sec;   // скільки секунд минуло від початку вікна :00/:30
secUntilNextWake = SleepDuration*60 - secIntoWindow;    // скільки лишилось до наступного :00/:30
secUntilNextWake -= WAKE_MARGIN_SEC (90);        // запас на дрейф RC-генератора OUTDOOR
```
Якщо NTP-час ще не отримано (`now < 1700000000` — ознака "годинник ще ніколи не синхронізувався", а не прив'язка до конкретного року) — надсилається запасний фіксований інтервал (`SleepDuration*60 - 90`) без вирівнювання по годиннику, аби OUTDOOR завжди отримував відповідь.

### Тестовий режим

```c
#define TESTING_DISABLE_DEEP_SLEEP
```
`BeginSleep()` не входить у реальний Deep Sleep — просто скидає стан і повертається, WiFi/ESP-NOW лишаються активними. **Обов'язково закоментувати перед реальною експлуатацією.**

## Відомі обмеження / на що звернути увагу

- Обидва пристрої мають бути на **однаковому WiFi-каналі** — INDOOR успадковує канал від реального роутера, до якого підключається; OUTDOOR має канал захардкоджений (`WIFI_CHANNEL`/`ESPNOW_WIFI_CHANNEL = 1`). Якщо роутер не на каналі 1 — ESP-NOW не працюватиме.
- Наразі відображається лише **один** активний набір "зовнішніх" даних (від останнього сенсора, який надіслав дані) — мультисенсорний UI (окремі секції на екрані для кожного) не реалізований.
- Обидва `TESTING_DISABLE_DEEP_SLEEP` прапорці зараз **увімкнені** в обох файлах — перед реальною експлуатацією на батареї їх треба закоментувати.
- Тиск (`pressure`) в ESP-NOW пакеті передається в сирих Паскалях, не в hPa — конвертація (`/100.0f`) відбувається лише на етапі відображення.
