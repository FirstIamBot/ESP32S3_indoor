# INDOOR — детальна документація

E-paper дисплей (LilyGo EPD47, 4.7", 960×540, ESP32 Arduino/PlatformIO), що є **ведучим (leader)** пристроєм метеостанції: отримує погоду з інтернету (OpenWeatherMap), читає локальні датчики (SHT21 + BMP085/180), приймає дані від зовнішнього(их) сенсора(ів) OUTDOOR по ESP-NOW, і синхронізує розклад сну обох пристроїв. Між циклами пристрій не перезавантажується — він використовує **Light Sleep**, а не Deep Sleep, що дозволяє миттєво реагувати на дотик до екрана без повного нового робочого циклу.

---

## 1. Апаратна конфігурація

| Призначення | Пін / адреса |
|---|---|
| I2C (SHT21, BMP085/180, DS3231, тачскрін) | SDA=15, SCL=14 (`Wire.begin(15, 14)`) |
| Кнопки | S2=GPIO34, **S3=GPIO35** (пошук нових сенсорів), S4=GPIO36, S6=GPIO4 |
| Сенсорна панель (переривання/пробудження) | `TOUCH_INT` = GPIO13, маска `TOUCH_PANEL` = GPIO_SEL_13 |
| DS3231 (RTC, резервний час) | I2C адреса `0x68` |
| WiFi канал (ESP-NOW) | `ESPNOW_WIFI_CHANNEL = 1` — має збігатись із каналом домашнього роутера |

⚠️ **Пін-конфлікт (успадкований з базового шаблону, не критичний зараз):** `S6 = GPIO4` збігається з лінією даних `D2` паралельної шини e-paper дисплея (`ed047tc1.h`). `S6` ніде не читається в поточному коді, тож конфлікту немає — але не можна почати використовувати цю кнопку без переносу на інший пін.

## 2. Життєвий цикл роботи

На відміну від класичної Deep-Sleep-схеми, `setup()` тут виконується **лише один раз** за все живлення пристрою (при подачі живлення або апаратному ресеті). Кожен наступний "робочий цикл" (WiFi/NTP/OWM/ESP-NOW) запускається явним викликом `StartNewCycle()` — або з `setup()` вперше, або з `BeginSleep()`/`QuickTouchWake()` одразу після пробудження з Light Sleep, без перезавантаження чіпа.

```
Живлення увімкнено ──► setup(): InitialiseSystem() ──► StartNewCycle() (перший цикл)
                                                              │
                    ┌─────────────────────────────────────────┘
                    ▼
      StartNewCycle(): ESP-NOW listener ──► WiFiManager ──► NTP ──► локальні датчики
                    │
                    ▼
      loop(): чекаємо OUTDOOR (до 10 хв) / показуємо дані / гортаємо сторінки дотиком
                    │
                    ▼
      BeginSleep(): Light Sleep до найближчої межі SleepDuration
                    │
       ┌────────────┴─────────────┐
       ▼ (таймер)                 ▼ (дотик, EXT1)
  StartNewCycle()            QuickTouchWake(): швидкий редрав кешем,
  (новий повний цикл)        назад у Light Sleep на решту часу
```

### Константи циклу

```c
#define OUTDOOR_MAX_WAIT_MS  (10UL * 60UL * 1000UL) // 10 хв - максимум очікування OUTDOOR
#define INDOOR_MIN_ACTIVE_MS (3UL  * 60UL * 1000UL) // 3 хв  - мінімум активності екрана
long SleepDuration = 30; // хвилин - періодичність сну
```

### `InitialiseSystem()` — виконується один раз за `setup()`

1. Serial, `epd_init()`, виділення фреймбуфера в PSRAM.
2. `InitialiseSensors()` — SHT21 + BMP085/180 по I2C.
3. `touch.begin()` — якщо не вдалося, пристрій зависає (`while(1)`).
4. Діагностика причини запуску (`esp_reset_reason()` — виявляє brownout/panic/power-on/deep-sleep).
5. `esp_sleep_enable_ext1_wakeup(TOUCH_PANEL, ESP_EXT1_WAKEUP_ANY_HIGH)` — вмикається **один раз назавжди**: дотик до сенсорної панелі буде будити пристрій з будь-якого наступного Light Sleep (обробляється в `QuickTouchWake()`, див. розділ 3).

### `StartNewCycle()` — весь "робочий" цикл (WiFi → OWM → сенсори)

```c
void StartNewCycle() {
  StartTime = millis();
  espNowDataReceived = false;
  cycleDataHandled = false;

  WiFi.mode(WIFI_STA);
  StartEspNowListener();                              // максимально рано - приймає пакети ще до WiFi

  bool wifiOK = (StartWiFi() == WL_CONNECTED && SetupTime());
  ReadLocalSensors();

  if (!wifiOK) {                                       // WiFi недоступний - показуємо, що є локально
    GetEspNowData();
    currentPage = 1;
    DisplayPage();
    return;
  }

  if (IsWakeTime()) FetchAndShowOnlineWeather();        // HTTP до OWM (лише в денний час)
  GetEspNowData();
}
```

### Що відбувається в `loop()`

Виконується безперервно (не блокує) до моменту сну:

```c
CheckDiscoveryButton();                                            // опитування кнопки S3

if (discoveryModeActive) { DisplayPage(); return; }                // режим пошуку сенсора

if (espNowDataReceived && !cycleDataHandled) {                     // дані від OUTDOOR прийшли вперше цього циклу
    GetEspNowData(); epd_poweron(); epd_clear();
    DisplayWeather(); edp_update(); epd_poweroff_light();           // показ - ОДИН РАЗ за цикл
    SendSyncAck(lastSenderMac);                                     // timestamp на OUTDOOR
    cycleDataHandled = true;
}

if (cycleDataHandled) {
    if (elapsed >= INDOOR_MIN_ACTIVE_MS) BeginSleep();               // мінімум активності минув -> спати
    else DisplayPage();                                              // ще чекаємо, тачскрін працює
    return;
}

if (elapsed < OUTDOOR_MAX_WAIT_MS) { DisplayPage(); return; }        // ще чекаємо OUTDOOR

BeginSleep(); // 10 хв вичерпано без даних - спимо без синхронізації
```

**Важливо:** `DisplayPage()` реагує лише на **фактичний дотик** (`digitalRead(TOUCH_INT)`) — сама по собі не малює нічого, якщо екрана ніхто не торкається. Тому початковий показ і показ даних OUTDOOR завжди йдуть напряму через `DisplayWeather()+edp_update()`, а не через `DisplayPage()`.

## 3. Сон (Light Sleep, не Deep Sleep)

Пристрій свідомо переведений на `esp_light_sleep_start()`. Light Sleep **не перезавантажує чіп** — RAM і всі глобальні змінні зберігаються так само, як і під час звичайної роботи, тому виконання просто продовжується одразу після виходу з функції сну (без повторного виклику `setup()`). Завдяки цьому доступне миттєве пробудження дотиком (`QuickTouchWake()`) без потреби піднімати WiFi/OWM/ESP-NOW заново.

### `BeginSleep()`

```c
void BeginSleep() {
  StopWiFi();            // WiFi.disconnect() + WiFi.mode(WIFI_OFF) - вимикає й ESP-NOW
  epd_poweroff_light();  // 3.3В-рейка лишається УВІМКНЕНОЮ - потрібна для тачскріна й Light Sleep

  UpdateLocalTime();
  SleepTimer = (SleepDuration * 60 - ((CurrentMin % SleepDuration) * 60 + CurrentSec)) + Delta;
  esp_sleep_enable_timer_wakeup(SleepTimer * 1000000LL);
  esp_light_sleep_start();

  // ---- виконання продовжується ТУТ ЖЕ після пробудження ----
  if (esp_sleep_get_wakeup_cause() == ESP_SLEEP_WAKEUP_EXT1) {
    QuickTouchWake();     // пробудження дотиком - швидкий редрав, назад у сон
    return;
  }
  StartNewCycle();        // пробудження таймером - новий повний цикл
}
```

- **`StopWiFi()` викликається лише тут** — єдине місце вимкнення радіо за весь цикл. Якщо викликати його раніше (наприклад, одразу після HTTP-запиту до OWM), ESP-NOW перестане приймати дані від OUTDOOR завчасно.
- **`epd_poweroff_light()`, а НЕ `epd_poweroff_all()`** — на відміну від Deep-Sleep-варіанту цього проєкту, 3.3В-рейка (і тоучскрін) навмисно лишається живою на весь час Light Sleep: без неї сенсорна панель не змогла б згенерувати сигнал пробудження на `TOUCH_INT`/`TOUCH_PANEL`. Це свідомий компроміс: трохи вище споживання в сні заради миттєвої реакції на дотик.
- `SleepTimer` рахується **вирівняно по годиннику** (до найближчої межі `:00`/`:30`, а не "рівно 30 хв від зараз") — це і є механізм синхронізації з OUTDOOR.

### `QuickTouchWake()` — швидке пробудження дотиком під час сну

Викликається одразу з `BeginSleep()` (і рекурсивно із себе самої), коли причина пробудження — `ESP_SLEEP_WAKEUP_EXT1` (дотик до `TOUCH_PANEL`):

1. Перемикає `currentPage` на наступну сторінку (`(currentPage + 1) % page`).
2. Малює екран **одразу наявними кешованими даними** (`DisplayWeather()` або `DisplayLocalWeather()`) — без WiFi, NTP, OWM чи ESP-NOW, тобто за секунди, а не хвилини.
3. `epd_poweroff_light()` — 3.3В лишається увімкненим, тачскрін готовий до наступного дотику.
4. Рахує залишок часу до найближчої межі `SleepDuration` напряму з **DS3231** (`DS3231_GetTime()`) — навмисно швидкий шлях, що не чекає підняття WiFi/NTP.
5. Знову йде в `esp_light_sleep_start()` на залишок часу.
6. Після повторного пробудження: якщо знову дотик — рекурсивно повторює швидкий редраw; якщо спрацював таймер — викликає `StartNewCycle()` (повний робочий цикл).

Завдяки цьому механізму розклад синхронізованого сну **не порушується** дотиками користувача — кожен дотик лише "вставляє" короткий редрав і повертає пристрій точно на ту саму годинникову межу.

### Точність синхронізації сну (важливі обмеження)

- Апаратний таймер `esp_sleep_enable_timer_wakeup()` на INDOOR — це, як правило, внутрішній RC-генератор (якщо немає зовнішнього кварца 32.768kHz), з похибкою в кілька відсотків → **десятки секунд** реального відхилення за 25-30 хв сну.
- INDOOR рахує **свій** сон без жодного запасу (на відміну від OUTDOOR, якому передається число з відніманими 45 сек запасу, див. розділ 4).
- Дрейф **не накопичується** з циклу в циклу, поки синхронізація вдається (кожен цикл рахується заново від актуального NTP/DS3231-часу) — але **якщо один цикл синхронізації провалюється** (OUTDOOR не отримав ACK), OUTDOOR падає на фіксований запасний інтервал без прив'язки до годинника, і розбіжність може сягати кількох хвилин до наступного вдалого циклу.

## 4. ESP-NOW

### Адресація — фіксований список MAC, без broadcast discovery

На відміну від ранніх ітерацій проєкту (broadcast `DISCOVER_SERVER`/`SERVER_ACK`), зараз INDOOR веде **список відомих MAC-адрес сенсорів** (до `MAX_KNOWN_SENSORS = 8`), збережений у NVS (`Preferences`, namespace `"sensors"`):

- `LoadKnownSensors()` — завантажує список при кожному старті (викликається зі `StartEspNowListener()`); якщо NVS порожній — підтягує один типовий сенсор за замовчуванням.
- `IsKnownSensor(mac)` — фільтр: пакети від невідомих MAC ігноруються (захист від сторонніх ESP-NOW пристроїв в ефірі).
- Усі відомі сенсори реєструються як ESP-NOW піри одразу при старті.

### Додавання нового сенсора — кнопка S3

1. Натискання **S3** → `discoveryModeActive = true` на 60 сек (`DISCOVERY_MODE_DURATION_MS`).
2. Поки активний — пакет правильного розміру (30 байт) від **будь-якого** невідомого MAC приймається як новий сенсор, реєструється як пір і зберігається в NVS через `SaveNewSensor()`.
3. Режим вимикається одразу після знаходження нового сенсора (або через 60 сек).
4. INDOOR **не йде спати**, поки режим пошуку активний.

### Структура пакета даних — `espnow_sensor_msg_t` (30 байт, `packed`)

```c
typedef struct __attribute__((packed)) {
  float   temperature;
  float   humidity;
  float   pressure;        // Pa (сирі паскалі!) - ділиться на 100 лише при відображенні
  float   batteryVoltage;
  uint8_t battery_percent;
  float   g_solar_voltage;
  uint8_t solar_percent;
  int64_t timestamp;
} espnow_sensor_msg_t;
```

⚠️ Має **побайтово** збігатися з `sensor_data_t` на OUTDOOR — будь-яка розбіжність призводить до мовчазного відкидання пакетів (`sizeof()` не збігається).

### `OnEspNowRecv()` — обробка вхідних пакетів

1. Логує MAC відправника і розмір пакета.
2. Фільтрує за `IsKnownSensor()` (окрім активного режиму discovery — див. вище).
3. Якщо розмір відповідає `espnow_sensor_msg_t` — копіює в `lastEspNowMsg`, запам'ятовує MAC відправника (`lastSenderMac`) для подальшого sync ACK, друкує розшифровані значення, виставляє `espNowDataReceived = true`.

### Sync ACK — `SendSyncAck()`

Надсилається **з `loop()`, після відображення даних на екрані** (не одразу з колбека прийому) — на MAC із `lastSenderMac`:

```c
time_t now = time(nullptr);
localtime_r(&now, &timeinfo);
secIntoWindow    = (tm_min % SleepDuration) * 60 + tm_sec;
secUntilNextWake = SleepDuration*60 - secIntoWindow;      // час до найближчого :00/:30
secUntilNextWake -= WAKE_MARGIN_SEC (45);                 // запас на дрейф RC-генератора OUTDOOR
```

Якщо NTP-час недоступний (`now < 1700000000` — ознака "годинник ще ніколи не синхронізувався", не прив'язка до конкретного року) — використовується **DS3231 як резервне джерело** (`DS3231_GetTime()`), а якщо і воно недоступне — фіксований запасний інтервал (без вирівнювання по годиннику), аби OUTDOOR завжди отримував якусь відповідь.

Структура ACK (5 байт, відрізняється розміром від пакета даних):

```c
typedef struct __attribute__((packed)) {
  uint8_t  magic;             // ESPNOW_SYNC_MAGIC = 0xA5
  uint32_t next_wake_in_sec;
} espnow_sync_ack_t;
```

## 5. DS3231 (резервний годинник)

- **`DS3231_SetTime()`** — викликається автоматично в `UpdateLocalTime()` щоразу, коли NTP спрацював успішно. Тримає RTC точним постійно, компенсуючи власний дрейф чіпа.
- **`DS3231_GetTime()`** — використовується як фолбек, коли NTP недоступний цього циклу; результат одразу встановлюється в системний час (`settimeofday()`), тож `time(nullptr)` і `SendSyncAck()` автоматично бачать коректний час.
- DS3231 **не має і не потребує "sleep"-режиму** — його осцилятор має продовжувати цокати весь час, незалежно від того, спить INDOOR чи ні; чіп сам по собі споживає одиниці мкА постійно.
- Використовується не лише як фолбек для `SendSyncAck()`, а й у `QuickTouchWake()` (розділ 3) — там саме DS3231, а не NTP, дає миттєвий відлік залишку часу сну без підняття WiFi.

## 6. Підключення до Wi-Fi — `WiFiManager`

З'єднання з роутером у `StartWiFi()` виконується через бібліотеку `WiFiManager`, а не жорстко заданими `ssid`/`password`:

```c
wm.setConfigPortalTimeout(180);   // 180 сек на конфігурацію, якщо немає збереженої мережі
wm.setConnectTimeout(30);         // 30 сек на спробу підключення до вже відомої мережі
bool res = wm.autoConnect("ESP32_Weather", "12345678");
```

- Якщо пристрій вже підключався до Wi-Fi раніше — `WiFiManager` використовує збережені в NVS дані й підключається автоматично (до 30 сек).
- Якщо мережа невідома/недоступна — піднімається точка доступу **`ESP32_Weather`** (пароль `12345678`) з конфігураційним порталом на 180 сек, де можна вибрати мережу через браузер.
- Якщо й це не вдалось — `StartWiFi()` повертає `WL_CONNECT_FAILED`, `wifiOK = false`, і `StartNewCycle()` одразу показує локальну сторінку (`DisplayLocalWeather()` через `currentPage = 1`), не чекаючи OWM.
- Після вдалого підключення перевіряється фактичний канал роутера (`WiFi.channel()`) проти `ESPNOW_WIFI_CHANNEL` — якщо вони не збігаються, у Serial друкується попередження (ESP-NOW від OUTDOOR може не прийматися).

⚠️ **`owm_credentials.h` досі містить константи `ssid`/`password`**, але вони більше **ніде не використовуються** в `.ino` — з переходом на `WiFiManager` це мертвий/застарілий код, залишений для довідки.

## 7. Багатосторінковий режим відображення

Екран має `page = 2` сторінки, поточна — `currentPage` (`RTC_DATA_ATTR`, хоча при Light Sleep це вже не є необхідним — значення й так зберігається в звичайній RAM):

| `currentPage` | Функція | Зміст |
|---|---|---|
| `0` | `DisplayWeather()` | Основний екран: погода з OWM, прогноз, графіки, астрономія |
| `1` | `DisplayLocalWeather()` | Порівняння **OUTDOOR** (дані з ESP-NOW: `extendet_*`) і **INDOOR** (локальні датчики: `local_*`) |

### Перемикання сторінок дотиком під час активного вікна — `DisplayPage()`

Виконується постійно з `loop()`, поки пристрій не спить. Реагує лише на **фактичний дотик** (`digitalRead(TOUCH_INT)` + `touch.scanPoint()`), розпізнаючи дві прямокутні зони:

- **лівий край** (`x: 5..250, y: 40..500`) → `currentPage--` (попередня сторінка);
- **правий край** (`x: 660..960, y: 40..500`) → `currentPage++` (наступна сторінка).

Після зміни сторінки — одразу `epd_poweron() → epd_clear() → Display... () → edp_update() → epd_poweroff_light()`.

### Перемикання сторінок дотиком під час сну — `QuickTouchWake()`

Окремий, незалежний шлях (розділ 3): дотик, що будить пристрій з **Light Sleep** (`ESP_SLEEP_WAKEUP_EXT1`), автоматично гортає на наступну сторінку (`(currentPage + 1) % page`) і перемальовує її кешованими даними, без очікування на WiFi/OWM/ESP-NOW.

## 8. Енергозбереження — підсумок і рекомендації

### Що вже реалізовано

| Механізм | Ефект |
|---|---|
| **Light Sleep** (`esp_light_sleep_start()`) замість Deep Sleep | Немає повного перезавантаження між циклами; дозволяє миттєвий редрав дотиком (`QuickTouchWake()`) без нового WiFi/OWM/ESP-NOW циклу |
| `epd_poweroff_light()` як під час активного вікна, так і перед сном | HV-рейки e-paper вимкнені між оновленнями екрана; 3.3В/тоучскрін лишаються живими — необхідно для пробудження дотиком (EXT1) |
| `StopWiFi()` лише один раз, перед сном | WiFi/ESP-NOW активні рівно стільки, скільки потрібно - не довше |
| Вирівняний по годиннику сон (`SleepTimer`) | Уникає зайвого "дострокового" пробудження порівняно з фіксованим таймером |
| DS3231-фолбек для sync ACK і для `QuickTouchWake()` | INDOOR не залежить виключно від WiFi/NTP для розрахунку розкладу сну |

### Можливі додаткові варіанти (не реалізовано, для обговорення)

1. **Повернення до Deep Sleep + `epd_poweroff_all()`** для проміжних очікувань — менше споживання в сні, але втрачається миттєве пробудження дотиком (`QuickTouchWake()`); має сенс лише якщо реакція на дотик під час сну не потрібна.
2. **Зменшення `OUTDOOR_MAX_WAIT_MS`/`INDOOR_MIN_ACTIVE_MS`** — коротший активний час = менше споживання, але вищий ризик пропустити OUTDOOR чи не встигнути показати дані користувачу.
3. **Зниження TX-потужності WiFi** (`esp_wifi_set_max_tx_power()`) — менший пік струму під час передачі, актуально при слабкому джерелі живлення; зменшує дальність.
4. **Зовнішній кварц 32.768kHz для RTC** (апаратна зміна) — значно точніший таймер сну, прибирає потребу в запасі `WAKE_MARGIN_SEC`.
5. **Динамічний `INDOOR_MIN_ACTIVE_MS`** — наприклад, скорочувати активний час вночі (коли `!IsWakeTime()`), якщо взаємодія з екраном малоймовірна.

## 9. Відомі обмеження

- Мультисенсорна NVS-адресація **фільтрує** дозволених відправників, але **відображає дані лише від останнього**, хто надіслав пакет — окремих секцій на екрані для кількох одночасних сенсорів немає.
- Тиск в ESP-NOW пакеті — сирі Паскалі; конвертація в hPa відбувається лише у функціях відображення.
- Обидва пристрої мають бути на **однаковому Wi-Fi каналі** (`ESPNOW_WIFI_CHANNEL = 1` на INDOOR визначається фактичним каналом роутера; OUTDOOR має канал захардкоджений — якщо роутер не на каналі 1, ESP-NOW не працюватиме).
- **Light Sleep споживає більше струму, ніж Deep Sleep** (3.3В-рейка й тоучскрін лишаються живими весь час сну) — свідомий компроміс заради миттєвої реакції на дотик.
- `owm_credentials.h` містить застарілі `ssid`/`password`, що фактично не використовуються (див. розділ 6) — потенційне джерело плутанини при подальшій підтримці.
